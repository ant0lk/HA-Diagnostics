# Диагностический ZIP

Версия продукта: `1.0.0-alpha.2`. Основной сценарий: владелец открывает дополнение через Home Assistant Ingress, нажимает «Собрать ZIP-архив», видит прогресс и скачивает готовый файл. Никакая настройка MCP, OAuth, ChatGPT или Tunnel для этого не требуется.

## Состав

| Каталог / файл | Содержимое |
| --- | --- |
| `logs/` | Журналы Core, Supervisor, хоста, DNS, Audio, CLI, Observer и Multicast |
| `logs/addon/` | Журнал каждого установленного дополнения, включая остановленные |
| `system/` | Версии и состояние Core, Supervisor, HA OS, хоста, аппаратуры, сети, служб, проблемы Supervisor, список сохранённых загрузок и текущая статистика |
| `home_assistant/` | Сведения о конфигурации из API, текущие состояния сущностей, каталог сервисов и типов событий |
| `registries/` | Реестры устройств, сущностей, областей и интеграций |
| `addons/` | Каталог дополнений, сведения и текущая статистика каждого |
| `integrations/` | Диагностика интеграций, предоставляемая самой интеграцией; поддерживаются старые hex ID и новые ULID |
| `history/00.json` … `23.json` | История Recorder за последние 24 часа, разбитая на часовые запросы с атрибутами состояний |
| `logbook/00.json` … `23.json` | Журнал событий за тот же интервал |
| `manifest.json` | Версия, начало/конец сбора, интервал истории, результаты и время чтения каждого источника, объём, SHA-256, причины пропусков |
| `README.txt` | Краткое описание и список частичных / недоступных источников |

Значения `false`, `0`, отрицательные числа, пустые строки и `null` сохраняются. Начало/конец истории фиксируются при запуске сбора в UTC. Локальный часовой пояс HA входит в сведения о конфигурации. Текущие снимки читаются последовательно и не представляют атомарный снимок установки.

## Все доступные логи

Экспорт использует конечные GET-чтения журналов с `Range: entries=:0:18446744073709551615`, начиная с самой старой доступной записи. Стандартный предел последних 100 строк и прежний предел 50 000 строк не применяются. Endpoint без `/latest` или фильтра загрузки запрашивает весь сохранённый журнал источника, включая доступные прошлые загрузки.

API и формат Range сверены с [официальной документацией Supervisor](https://developers.home-assistant.io/docs/api/supervisor/endpoints/) и [реализацией LogsControl](https://github.com/home-assistant/supervisor/blob/main/supervisor/host/logs.py). История и события читаются через [REST API Home Assistant](https://developers.home-assistant.io/docs/api/rest/). Диагностика интеграций — через [Core diagnostics API](https://github.com/home-assistant/core/blob/dev/homeassistant/components/diagnostics/__init__.py).

Удалённые журналы и уже очищенная история не восстанавливаются. Отсутствие Recorder / Logbook / diagnostics, отказ в доступе, ошибка или разрыв соединения записываются как `unavailable` / `partial` с фиксированным кодом причины. Сбор остальных источников продолжается. Завершённое чтение не доказывает полноту исторических данных: в manifest отдельно указаны неизвестные retention/exclusions.

## Очистка и доступ

Исходные данные проходят очистку в отдельном credential worker до записи в ZIP. Логи обрабатываются потоком, включая многострочные PEM-блоки; полный журнал не загружается в память. Токен Supervisor не передаётся процессу интерфейса, MCP или транспорту. UI обращается к конечным IPC-командам; peer UID проверяется ядром Linux. Все обращения к HA — GET или фиксированные команды чтения WebSocket. Управление устройствами, перезапуск или изменения конфигурации отсутствуют.

Распознаваемые секреты, значения полей credentials и options/schema дополнений удаляются. Имена, entity ID, адреса, MAC и email очищаются/псевдонимизируются существующим локальным Redactor. Нативные registry ID сохраняются для связи записей. Файлы `/config`, `.storage`, `secrets.yaml`, база Recorder, медиа и приватные файлы самого дополнения не копируются. Неизвестный секрет может не распознаться: перед передачей файла следует просмотреть содержимое.

Скачивание проверяет ту же подтверждённую Ingress-сессию владельца, что и панель. POST-команды дополнительно защищены CSRF. Файл выбирается только по проверенному ID архива в фиксированном каталоге; путь от клиента не принимается. ZIP скачивается потоком, без чтения целиком в память. Каталог экспорта доступен credential worker и UI, но не query worker.

## Хранение и пределы

Сохраняются последние 3 готовых архива до 24 часов; очистка выполняется при запуске worker и создании очередного экспорта. Завершённые архивы доступны после перезапуска. Отмена удаляет недописанный ZIP. Перезапуск сбора создаёт новый файл. Собранные архивы исключены из HA backup.

Пределы защиты дополнения: 128 MiB входящих / очищенных данных на источник, 512 MiB очищенных данных на весь набор (служебный manifest и README отдельно), 32 MiB на JSON-ответ, 1 MiB на строку лога, минимум 100 MiB свободного диска, до 5 минут на источник логов и до 90 секунд на JSON-чтение. При достижении предела manifest указывает причину; архив не выдаётся как полный. Это конечный диагностический экспорт, не непрерывная подписка.

## Проверка и совместимость

Локальная демонстрация: `python -m ha_diagnostics.runtime --demo --data .local-data --web web`. Демо не обращается к HA и явно помечает архив тестовым. Тесты `tests/test_zip_export.py` проверяют состав ZIP, более 50 000 строк, 24 часовых окна каждого вида истории, очистку, SHA-256, частичные источники, лимиты, отмену, восстановление скачивания и запрет неавторизованного доступа.

После изменения исходников копии в `ha_diagnostics_live/app/src` и `app/web` должны совпадать с основными. Slug `ha_diagnostics_live` и текущая версия сохраняются. Старые компоненты MCP и локальные настройки сохранены; для прежнего режима нужен явный `--workflow mcp` / `HAD_WORKFLOW=mcp`. В ZIP-режиме они не запускаются.

На реальной HA OS ещё нужно проверить: установку/обновление, Ingress ID владельца, Linux UID/IPC, доступность конкретных API и скачивание большого ZIP через HA Ingress. Локальные fixtures подтверждают кодовый контракт, а не эти live-проверки.
